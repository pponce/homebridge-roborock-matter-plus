## Replacement PR description

An account MQTT session can remain connected while replies stop. This opt-in recovery recreates the client through the shared readiness gate from #37 and retains the breaker integration from #30.

Recovery is single-flight. A replacement that misses its readiness deadline continues reconnecting; missing clients and connected-but-unacknowledged replacements have bounded retry handling. Preventive refresh checks pending work before pausing sends. Preventive and health refreshes use the short recreation cooldown; only silence recovery consumes the 30-minute silence cooldown.

Ordinary and recovery connections share connection-state logging and v3.39.0 client-retirement guards. mqtt.js's own listeners remain installed, QoS-zero queueing remains disabled, and teardown abandons pending requests without inventing a robot reply. Diagnostics include recovery reason/result, failures, cooldowns and the last eligible observation tagged with its generation.

Based on v3.39.0 plus #37, with #30's integration included. Merge #30 and #37 first; align this branch again if either changes. The unrelated probe fix and broader shutdown-order change are excluded. Refs #27.
