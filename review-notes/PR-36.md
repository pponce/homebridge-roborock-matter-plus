Suggested title: **Distinguish retained MQTT presence from live robot reports**

## Replacement PR description

Retained presence is a broker snapshot, so it should not establish the robot's live presence baseline or be announced as a recovery.

Retained snapshots stay debug-only. The first live report produces one informational line per robot; unchanged repeats are suppressed. Later live transitions retain useful logging. Offline wording no longer implies that LAN commands must fail.

The suite includes a real loopback MQTT broker that sends a retained snapshot followed by a live report, checking mqtt.js's packet.retain flag and the resulting logs.

Based directly on v3.39.0 and limited to presence logging. It uses upstream's existing retired-client guard and excludes the SUBACK defensive change, TCP-probe test fix and momentary-action behavior. Retained-only behavior on physical robots remains an observation to collect, not a claimed live test.
