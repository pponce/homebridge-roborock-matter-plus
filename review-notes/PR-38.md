Suggested title: **Persist confirmed schedule state and report unknown write outcomes**

## Replacement PR description

Schedule switches acknowledge acceptance immediately and display the requested state provisionally while reconciliation runs. Confirmation remains separately persisted in accessory context, including before Homebridge saves its cache during shutdown.

Explicit failures restore the latest confirmed display and log the robot, Home switch name, requested/restored values, elapsed time and failure reason. Newer intent is protected from older failures. Restart restores saved confirmation and logs the interrupted request.

An unverified write is outcome unknown, not a confirmed failure. It does not arm the failed-command cooldown. One follow-up read is scheduled under the account queue and throttle policy; fresh source data logs the resolution and any correction. Failed source data cannot confirm the result.

Timing is typically 5–8 seconds, can exceed a minute with ambiguous write plus fallback, and includes any queueing behind other robots. Real hap-nodejs tests cover post-onSet ordering, retaps, cache-before-shutdown restoration, unknown outcomes and shutdown.

Based on standalone #32 over v3.39.0. No momentary-action or MQTT recovery changes. The maintainer will write the release note. Live Apple Home observations remain pending before this leaves draft.
